# 环境与能力检查设计

状态：目标检查契约，已实现的子集见 [实现状态](implementation-status.md)。2026-10-19 用户完成 Xcode 协议后，Xcode 27.1／iOS SDK 27.1 与 iOS 26.5 模拟器已可读取并运行。未连接的 iPhone 13 mini 由用户后续在 iOS 27.2 手工验收，签名与真机性能不由模拟器结果代替。

当前源码采用 `ExportReadiness` 对计划、文件、编码配置、容量与热状态做按次预检，并在实际 I/O 失败时保留草稿；设置展示本机资源和在线请求状态。下表中的完整 `ReadinessReport` 多态接口、模型检查、脱敏诊断导出等仍是扩展目标，不能视为全部已经实现。HTML 预检状态仅为交互演示。

## 1. 开发机检查

这些项目在 Mac 上处理，普通 App 页面不显示“安装 Xcode／Python／FFmpeg”。

| 检查 | 方法与通过条件 | 失败后的行动 |
| --- | --- | --- |
| Xcode 路径、版本、许可与首次启动组件 | 指定 `DEVELOPER_DIR`，检查 `xcodebuild -version`、`-checkFirstLaunchStatus` | 在 Xcode 内阅读并确认许可、完成组件初始化；不得由代理代为接受协议 |
| iPhoneOS SDK | `xcodebuild -showsdks`，SDK 满足实际采用的 API | 在 Xcode 下载所需平台；SDK 存在不等于模拟器 runtime 存在 |
| Simulator runtime 与设备 | `simctl list runtimes`、`simctl list devices available`，再实际启动目标模拟器 | 安装对应 runtime；只使用检查输出中的设备 ID |
| 真机 | `devicectl list devices`，在 Xcode Devices 中核对 iOS 版本、信任、配对、Developer Mode | 由用户完成设备解锁和系统确认 |
| 签名与部署目标 | Personal Team、稳定 Bundle ID、自动签名；deployment target 不高于手机系统，SDK 支持该系统 | Xcode 中解决签名；用真机 Run 验证，模拟器编译不证明签名有效 |
| 工程与测试 | 共享 scheme、测试 target、模拟器 build/test、真机 build/run | 记录准确命令及结果；工程不存在时这些检查为“未执行” |
| 依赖与资源 | 首轮只用系统框架；后续包固定版本并提交解析锁文件；核对字体许可与打包资源 | 缺字体／模板属于构建或安装问题，通过更新 App 修复，不在手机上下载桌面可执行工具 |
| 桌面对照样例 | 在现有 CLI 环境运行相关样例；记录输入、输出与配置 | Node／uv／FFmpeg 只属于桌面对照路径，不能成为 iOS build 的必需依赖 |

协议完成后，按主说明书 Step 0 的命令重新检查，再创建工程。协议确认和账号验证由用户完成；组件下载与首次启动初始化可在开发任务已授权时执行。不要为查看版本修改全局 `xcode-select` 或安装新包。

## 2. App 内采用按操作判定的能力检查

复用现有 `web/src/capabilities.ts` 的集中派生思想，而不是复制桌面 doctor 的依赖清单。建立 `CapabilityService`，接受具体 `OperationRequest` 和 `ProjectSnapshot`，输出 `ReadinessReport`。

每条结果包含检查 ID、受影响的操作、状态、用户文案、可执行补救、检查时间，以及适用的作品 revision／服务／模型版本。状态至少为 `checking`、`ready`、`warning`、`blocked`、`unknown`、`notApplicable`。必需项的 unknown 不能当 ready；不适用项不阻塞。不要提供一个控制全 App 的全局 `ok`。

需要区分的操作：导入照片、导入音频、预览、导出 PNG、导出 MP4、保存到系统照片、在线找歌词、在线生成旁白、本机识别、下载模型、备份／恢复。

| 检查 | 触发时机与内容 | 影响与呈现 |
| --- | --- | --- |
| 素材 | 导入时校验文件、格式、方向、尺寸；导出时确认副本存在且可解码 | “2 张照片尚未下载完成” → 继续下载／移除这些照片；已有本地素材不因断网失效 |
| 作品与时间线 | revision、照片顺序、时长、字幕范围、素材覆盖、模板资源 | “这段音乐放不下全部照片” → 调整时长／减少照片；禁止静默丢图 |
| 渲染引擎与资源 | 构建期检查链接框架及 deployment target；首次使用检查 CIContext／所需 GPU 资源初始化、字体注册与模板资源加载 | “当前样式无法加载” → 换可用样式／更新 App。内置资源缺失不能显示为“请安装 FFmpeg”；缓存检查结果按 App／OS 版本失效 |
| 编码配置 | 对当前 MP4 请求调用 AVAssetWriter 的配置兼容性检查，并处理 writer 创建／启动失败 | “当前输出规格不可用” → 换受支持规格；配置检查通过不等于导出或硬件加速已验证；PNG 不受 MP4 编码项阻塞 |
| 磁盘 | 导入、模型下载、备份和导出前查询实际可用容量；计入素材、视频中间件、最终文件及安全余量 | “预计还需 420 MB” → 管理空间；数字必须来自当前估算，不能硬编码。运行中仍处理磁盘写满 |
| 任务占用 | 原子申请单一渲染／重分析槽；检查关联作品锁 | “已有作品正在制作” → 查看任务。初检通过后仍须在启动事务内再次确认 |
| 温度与电量 | 观察 thermalState、低电量模式和可用电池状态；初始策略：serious 警告并降低预览负载，critical 不启动重任务 | “设备较热，建议稍后制作”；低电量模式本身不封锁出片。运行中的终止／降载策略需真机测定，不做精确剩余时间保证 |
| 内存 | 解码限流、缓存预算、内存告警、失败清理；开发期用 Instruments 测量 | 不显示“剩余内存足够，保证成功”。系统回收可能没有回调；必须有启动恢复 |
| 系统照片写入 | 用户点“保存到照片”时查询并请求 add-only 权限 | 被拒绝只阻塞保存到图库，作品留在 App 内，仍可分享或保存到文件；选片不提前申请全图库权限 |
| 音频与识别权限 | 导入音频仅检查文件访问和解码；自带离线推理模型不以麦克风权限为前置条件 | 不为处理已有歌曲申请录音权限。若以后选用 Apple Speech 服务，另行核对其授权和离线能力，不能套用自带模型的判断 |
| 文件权限 | 导入时取得安全作用域访问并复制，导出备份时处理文件选择器取消与失败 | “无法读取这个文件” → 重新选择；不长期依赖临时 URL |
| 在线服务 | 按歌词源／旁白源分别记录请求结果；识别断网、TLS／DNS、超时、401/403、429、服务故障 | “歌词来源暂时不可用” → 换来源／导入 LRC；不影响本地出片。NWPathMonitor 仅表示网络路径状态，不能证明 VPN、API 或某网站可访问 |
| API Key | 配置存在、Keychain 可读，与服务实际请求成功是不同状态 | 显示“已配置，尚未验证”或最近调用失败。仅由用户动作触发联网验证；不为了检测自动上传照片或消耗付费生成额度 |
| 本机识别模型 | 清单版本、下载完成、摘要、推理引擎与系统兼容性、首次加载；下载用临时文件并提交 | “模型未下载” → 查看体积并下载。损坏时只重下损坏模型；模型不可用不影响 LRC／在线歌词或普通视频 |
| 模型空间清理 | 检查模型是否在运行任务中被使用 | 使用中禁止删除；可重下模型不进入作品备份，照片与编辑清单不能作为缓存清掉 |

初检应在本地快速完成；可耗费网络、GPU 或模型加载的检查不能在每次切 Tab 时重跑。静态能力按 App／OS／资源版本缓存；网络结果注明服务与时间；项目 revision、Key／模型改变时使相关结果失效。用户按下制作后，在固定快照、申请任务槽、核对容量的同一流程中复检，避免检查后素材已变化。

## 3. 页面怎么呈现

**日常操作附近显示必要信息。** 照片导入显示每张下载状态；旁白按钮附近提示未配置 Key；本机识别入口显示模型大小与下载状态。信息只影响对应动作，不在首页放一整屏红色“环境不完整”。

**预览页的制作按钮仍在滚动内容中。** 点击后进入预检：快速通过则直接开始；有阻塞时在当前内容区显示问题和修复按钮，不增加第二层固定底栏。修复后“重新检查”。只有警告时明确“仍然制作”；必需项失败或未知不提供强行绕过。保存到系统照片的权限在导出完成后再处理。

**设置增加“使用状态”。** 分组显示“本机制作”“在线服务”“可选模型”，说明最近检查时间，提供“重新检查”“管理空间”“配置旁白服务”等动作。健康状态不需要常驻打扰。高级详情可复制脱敏诊断：App／OS 版本、设备型号、operation、错误代码、阶段和时间；不包含 Key、用户照片、歌词正文、私人文件路径或完整服务返回内容。

原型新增的“使用状态”页和预检示例只演示表现位置。示例可切换空间不足／可用，不能视为电脑或手机的真实检测结果。

## 4. 必需验收案例

- 断网、无 Key、无识别模型时，本地照片＋无声视频及 PNG 都能完成。
- 音乐存在但无歌词时仍可制作；不自动启动识别或下载模型。
- 模型未下载／损坏只阻塞本机识别，旁白 Key 无效只阻塞新的 AI 生成，已有文字仍可使用。
- 图库写入被拒绝时导出文件不丢，分享仍可用；照片导入不要求全图库权限。
- 初检后空间变化、素材缺失或 revision 变化，启动／写入阶段能再次处理并保留草稿。
- 网络路径可用但 API 401、429、超时分别给出准确文案；不把所有错误说成“VPN 未打开”。
- 进程被杀后，启动时找到中断任务；没有半成品被标为成功，也不删除其他作品的缓存或成果。
- 预检错误与较大字体均可滚动查看；制作按钮和修复入口可达，只有一个底部导航层。
