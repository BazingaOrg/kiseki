# ADR：任务不支持中断恢复，采用可证明所有权的清理策略

日期：2026-07-28
状态：已实施，待用户 QA

## 背景

视频、静态导出、抓取与分析都会创建进程、临时文件和中间产物。此前的 job 观察与锁定仅能描述同一服务中的当前任务，不能安全地把刷新页面、服务重启或遗留文件解释为可恢复进度。

## 决策

1. **不实现中断恢复。** 取消、服务退出，或下次启动发现异常残留时，均终止该任务的整个进程树、清理其 `partial`/临时目录，并从头开始。页面刷新只能观察同一服务进程仍在运行的当前任务；刷新不是恢复协议。
2. **lease 不是进度日志。** lease 仅用于跨进程互斥、记录 owner 身份和定位清理对象；不写入或重放阶段、百分比、命令输出、可续跑参数或任何持久化进度。
3. **owner 存活时拒绝竞争。** 发现有效 lease 且 owner 仍存活时返回 `409`，不接管、不杀掉、不清理。只有能证明 owner 已死亡时才可清理其任务残留并释放 lease；无法证明时 fail-closed，保留残留并拒绝开始新任务。
4. **每个任务独占 temp root。** 任务运行目录不得与其他任务、用户回收站或共享缓存复用。最终结果先写入任务私有 `partial`，成功后以原子 rename/replace commit 到正式目标；失败、取消和异常退出不能留下被扫描为完成品的半成品。
5. **终止采用两阶段并等待回收。** 先发 TERM，等待有限时间；仍未退出则发 KILL，再等待 `close`/reap。只有确认子进程树已结束并被回收后，才删除对应临时目录和 lease。Unix 以进程组/会话管理整棵树；Windows 以 Job Object 或等价的 `taskkill /T` 路径管理树，不能只杀父 PID。
6. **清理有明确排除项。** `.tsuzuri-trash` 是用户可撤销的回收站，自动任务清理不得删除；`.remotion`、模型文件及缩略图缓存是共享缓存，也不得按单任务删除。它们另按各自的失效或用户主动清理策略处理。

## 后果

- 好处：不把不完整状态误报为可恢复，跨进程竞争在证据不足时保持安全，半成品不会污染结果扫描。
- 代价：取消、崩溃后的工作必须重做；用户需要重新发起任务，而非期待跨服务恢复。
- 约束：lease 的所有权证明、PID/启动时间/平台标识必须防止 PID 重用误判；若证明链不充分，应拒绝而不是猜测清理。

## 不做的事项

- 不建立持久化任务队列、checkpoint、日志重放或跨服务进度订阅。
- 不自动清空用户回收站或共享渲染/模型/缩略图缓存。
- 不将“浏览器仍显示旧进度”视为服务仍拥有可恢复任务的证据。

## 实施说明与边界（2026-07-28）

- 未实现任何真正的 resume。页面在同一服务进程内刷新时，只会重新观察仍存活的内存 job；取消或正常退出后会清理并从头开始，不能恢复原任务。
- 服务收到可处理的 shutdown 信号时走 TERM→等待→KILL→等待 close/reap 的受限清理。SIGKILL 会直接终止服务，服务无法运行 finally；durable lease 会阻止重叠写入，下次启动仅能清理可证明归属的已知 group/snapshot，不能绝对保证发现独立 daemonize 且未被观察到的后代。
- `.tsuzuri-trash` 不自动清理；只有完整 undo 成功后才删除本次 operation，未来显式 empty-trash 尚未实现。旧 `.tsuzuri-fetch-*` 不会被盲删。
- 歌曲与歌词搜索候选各限制为 10 条，并以稳定 provider ID 做保守去重。
- 最终静态审查为 PASS。修复了 direct interactive render 的 lease reattach、TERM 后 root 已死的 descendants KILL、spawn PID/start 登记竞态、Windows identity/liveness gate，以及 jobs 单测对真实 runtime registry 的耦合。
- 未运行 tests、build、browser、render、network 或真实 signal 验证；上述运行时与媒体 QA 由用户负责。
