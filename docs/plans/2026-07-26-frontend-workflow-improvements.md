# Web 工作流改进：受控步骤、统一资产展示与安全文件操作

日期：2026-07-26
状态：**三批已实现，待用户验证**
性质：设计与执行记录；实际实施情况见本文的 Implementation Notes。

## 1. 背景与范围

当前 Web 工作台已经把素材、制作和成果放进同一工作区，但导航仍保留可自由切换的 Tab 语义；成果内容纵向堆叠，素材照片也只展示前 12 张。与此同时，网页的在线搜歌/歌词匹配所显示或落盘的文件名，与 CLI 的“歌名 - 歌手”约定未完全一致；素材页还会把用户跳回自己当前所在的素材页。

本计划只覆盖以下七项体验与契约调整：

1. 成果区改为局部 Tab，避免成片、音乐歌词、图片纵向竞争。
2. 统一 Web 与 CLI 的音乐、歌词命名和确认过程。
3. 素材与成果共享资产展示能力，素材照片可查看全部并可放大浏览。
4. 规划安全的删除与重命名，但将写文件操作放在第三批。
5. 对齐制作页“渲染相册视频”与“导出静态作品图”的操作按钮。
6. 主导航改为“素材 → 制作 → 成果”的受控步骤条。
7. 移除素材页中无意义的“去补素材”自跳，并重定义阻塞提示的动作语义。

本计划**显式调整** [2026-07-25 Web 工作台重构计划](2026-07-25-web-workbench-redesign.md) 中“主区三段可自由跳转、只在能力粒度锁定”的决定：此次改为页面级受控步骤，仍允许用户回看已完成步骤和已存在成果。

## 3. 七项结论

### 3.1 成果页：局部 Tab，不再纵向堆叠

成果页采用 `成片 / 音乐与歌词 / 图片` 三个局部 Tab，默认选择最有内容、最符合当前动作的分类：有新成片时默认“成片”；从素材页进入图片时默认“图片”；无成片但有音乐时默认“音乐与歌词”。Tab 标题显示数量或缺失状态，但不把空态隐藏：用户应能知道该类成果尚未产生。

这比三个完整区块纵向排列更适合以预览为主的页面：媒体播放器获得足够高度，歌词不会被照片墙推到下方，图片也可使用完整可滚动的网格。它只作用于成果页内部，不与主步骤条混淆。

### 3.2 音乐与歌词：最终命名统一为“歌名 - 歌手”

Web 搜索结果选定后，先展示并允许确认三个字段：`歌名`、`歌手`、`最终文件名`。默认最终文件名为 `歌名 - 歌手`，音频和对应歌词使用同 stem（例如 `晴天 - 周杰伦.mp3` 与 `晴天 - 周杰伦.lrc`）。

不得将搜索结果的 uploader/channel 直接当成歌手；仅在上游明确提供 artist 时预填“歌手”，否则要求用户确认或编辑。下载 API 接受经过结构化确认的 `title`、`artist` 与 `fileStem`，服务端再次校验 stem，CLI 与 Web 复用同一个规范化/冲突检测函数，避免两端各自拼接文件名。

### 3.3 素材页：全量图片 + Lightbox，底层与成果复用

素材页不再截断为前 12 张。照片缩略图区使用已有 `PhotoGrid` 的懒加载、点击、查看器能力，提供“全部照片（N）”与 Lightbox 内的前后切换/计数。成果页的照片分类同样走该能力，但两页保留各自业务壳：

- 素材页显示源照片、音频、歌词和“缺什么/如何补齐”；允许部分为空。
- 成果页显示成片、作品图、音乐与歌词，并以预览/回看为主。

建议抽取 `AssetCollection`、`ImageGallery`、`AssetItem`、`FileActionMenu` 等底层组件，而不是把 `Materials` 与 `Results` 合为一个大组件。

### 3.4 删除与重命名：值得做，但必须第三批、可恢复且有依赖规则

文件操作不与只读 UI 或资产模型同时上线。先建完整资产清单与 API 契约，再开放单文件重命名、可恢复删除和撤销。禁止“直接永久删除”。

删除移动至项目内 `.tsuzuri-trash/` 并记录可撤销信息；运行中的任务拒绝操作并返回 `409`；重名冲突返回 `409`。服务端只接受资产清单中允许的媒体叶子节点，逐次验证 token、`realpath`、目标父目录和软链接逃逸，不能依赖浏览器传来的任意路径。

### 3.5 制作页：ActionCard 统一五层布局

两张制作卡统一为：`标题/说明` → `状态或前置条件` → `参数区（可伸展）` → `说明/错误` → `footer 操作区（固定底部）`。卡片使用 grid/flex column，参数区 `flex: 1`，footer 置底；因此“开始渲染”和“开始导出”始终同一基线。移动端再自然纵向排列，不为桌面视觉对齐牺牲可读性。

### 3.6 主导航：改为受控步骤条

未选择文件夹时只显示欢迎页。选择后顶部主导航为 `素材 → 制作 → 成果`：当前可做的一步高亮，未满足条件的后续步骤锁定；已经完成的步骤可返回查看。步骤条管理“跨区流程”，各页内仍保留其必要的局部交互（成果 Tab、素材操作卡、制作参数）。

### 3.7 “去补素材”：抑制自跳，改为真实补救动作

素材页面的 Blocked 组件复用了通用 remedy 跳转，当 remedy target 正好是当前素材步骤时，就产生“去补素材”自跳。短期在 `Blocked` 层抑制同 target 跳转，只显示具体缺失说明；有可执行补救时改成语义动作，例如“在线找一首歌”“选择歌词文件”“查看缺少的照片”。长期应让 capability 返回 `action`（命令/弹窗/文件选择）而不是抽象的页面 target。

## 4. 推荐信息架构

```text
未选文件夹
└─ 欢迎页：选择素材夹

已选文件夹
├─ 步骤 1 素材（可回看）
│  ├─ 照片：全量网格 + Lightbox
│  ├─ 音频：已选文件或获取动作
│  └─ 歌词：已选/识别结果或可选的补齐动作
├─ 步骤 2 制作（按条件解锁，可回看）
│  ├─ 渲染相册视频
│  └─ 导出静态作品图
└─ 步骤 3 成果（有成片解锁，可回看）
   ├─ 成片 Tab
   ├─ 音乐与歌词 Tab
   └─ 图片 Tab
```

## 5. 素材状态与页面表达

| 状态 | 判定 | 素材页 | 制作页 | 成果页 |
| --- | --- | --- | --- | --- |
| empty | 照片、音频、歌词均无 | 展示三个空位及具体补齐动作 | 视频渲染不可用；静态图也因无照片不可用 | 锁定，除非已有历史成片 |
| partial | 有照片无音频、只有音频无照片、或歌词缺失 | 展示现有资产与缺失项；歌词明确为可选 | 视频取决于照片+音频；静态图只需照片 | 无视频时锁定；已有历史成片仍可查看 |
| complete | 照片+音频齐全，歌词可有可无 | 显示完整资产并允许进入制作 | 视频可用；静态图可用 | 有视频后解锁 |
| ambiguous | 多音频/多歌词或无法可靠确认歌手/名称 | 要求用户选择主资产或确认歌曲字段，不隐式猜测 | 依赖主音频的视频渲染保持不可用 | 已有成片可看，但不能据此重做 |

## 7. 文件类型影响矩阵

| 资产 | 允许操作（第三批） | 重命名副作用 | 删除副作用 | 特殊约束 |
| --- | --- | --- | --- | --- |
| 源照片 | 重命名、可恢复删除 | 同步 `tsuzuri.json.perPhoto`；使 timeline/分析缓存失效 | 同样使计划失效，保留垃圾箱记录 | 只允许受支持图片叶子 |
| 主音频 | 重命名、可恢复删除 | 与同 stem 的 `.lrc` 原子成对改名 | 视频重做条件失效；历史成果仍可看 | 多音频须先选定主资产 |
| 同 stem 歌词 `.lrc` | 跟随主音频成对改名；可恢复删除 | 必须与音频同事务 | 仅影响歌词体验，非视频硬门槛 | 不允许改成与音频不一致的 stem |
| 非同 stem 歌词 | 本批只读展示 | 不改变当前唯一 LRC 的使用语义 | 不级联删除 | 唯一 LRC 无论 stem 均是当前歌词；音频操作仅联动同 stem LRC |
| 成片/静态成果 | 重命名、可恢复删除 | 不级联源素材与 metadata | 删除最后视频会重锁成果步骤 | 相对安全，但仍在沙箱和任务冲突规则内 |
| metadata JSON | 不开放 | — | — | 不作为用户可操作资产 |

## 9. 分三批实施计划

### 批次一：受控工作流与只读展示

目标：不新增任何文件写操作，先完成可理解、可浏览、不会自跳的体验。

1. 建立 `deriveWorkflowSteps`，把能力、已有成果、运行任务推导成第 6 节的状态表。
   - 影响文件：`web/src/Workbench.tsx`、`web/src/capabilities.ts`，以及对应测试。
   - 关键决定：历史成片优先保证可回看；静态图和歌词均不解锁成果。
   - 风险：不能把“制作不可重做”误显示为“成果不可看”。
   - 验证：纯函数覆盖未选文件夹、empty/partial/complete/ambiguous、运行中、旧项目、删除最后视频等用例。
2. 改造成果局部 Tab，抽取只读资产展示/图片画廊层，素材页接入全量照片与 Lightbox。
   - 影响文件：`web/src/Results.tsx`、`web/src/Materials.tsx`、`web/src/PhotoGrid.tsx`、新增共享组件、样式文件。
   - 关键决定：共享底层能力，不合并两个业务页面。
   - 风险：大文件夹的首屏性能与 Lightbox 焦点/键盘可访问性。
   - 验证：浏览器检查 0、12、13、数百张照片；图片惰性加载、键盘切换、Esc 关闭；成果三个 Tab 空/满组合。
3. 统一制作卡片结构，抑制素材页同 target 的 Blocked 跳转。
   - 影响文件：`web/src/Make.tsx`、`web/src/Materials.tsx`、`web/src/ui.tsx`、`web/src/App.css`。
   - 关键决定：footer 固底、参数区伸展；无真实补救操作时只解释，不链接回当前页。
   - 风险：窄屏时卡片高度不一致或 action 溢出。
   - 验证：桌面同基线截图/DOM 检查；窄屏布局；所有 Blocked 状态无“去补素材”自跳。

### 批次二：统一资产模型与搜歌/歌词命名契约

目标：先让页面准确描述真实文件与命名，再把写操作接入。

1. 扩展项目扫描返回全量 `audios`、`lyricsFiles` 与稳定资产信息，显式表达主资产和歧义。
   - 影响文件：`cli/web-api/project.mjs`、`web/src` 的项目类型与消费点、API 测试。
   - 关键决定：多候选必须显式选择，不通过数组第一项隐式决定。
   - 风险：旧项目中不规范命名/多文件的兼容展示。
   - 验证：无文件、单文件、多音频、多歌词、已有输出项目的 API 和 UI 用例。
2. 抽取 Web/CLI 共用的歌曲字段确认、stem 生成、扩展名和冲突校验。
   - 影响文件：`cli/fetch.mjs`、`cli/web-api/fetch.mjs`，必要时新增窄的共用模块及测试。
   - 关键决定：默认 `歌名 - 歌手`；uploader 不是 artist；最终文件名在下载前可确认。
   - 风险：不同来源元数据缺 artist、非法文件名和已有同名文件。
   - 验证：CLI 与 Web 对同一输入生成相同 stem；无 artist、用户改名、同名冲突、音频+LRC 同 stem 测试。
3. 将素材/成果页接到统一资产模型，并完成只读状态回归。
   - 影响文件：批次一的展示组件、`Results.tsx`、`Materials.tsx`。
   - 关键决定：保留各自业务壳，展示数据由同一资产集合提供。
   - 风险：接口变更遗漏旧的单字段消费者。
   - 验证：类型检查、项目 API 契约测试、浏览器 smoke test。

### 批次三：安全的重命名、可恢复删除与撤销

目标：开放基础文件管理，同时保持项目可恢复、任务一致和沙箱安全。

1. 设计资产操作 API 和服务端授权/路径校验。
   - 影响文件：`cli/web-server.mjs`、`cli/web-api/sandbox.mjs`、新增 asset API 模块与测试。
   - 关键决定：仅 token 鉴权的结构化 `assetId` 操作；服务端重新从清单解析路径；运行中/同名冲突均为 `409`。
   - 风险：软链接、路径穿越、TOCTOU、并发任务。
   - 验证：缺/错 token、目录/metadata 操作、`..`、软链逃逸、未知 assetId、运行中、冲突用例均拒绝。
2. 实现项目内 `.tsuzuri-trash/`、删除/撤销与原子重命名。
   - 影响文件：新增文件操作模块、`cli/project.mjs`、`cli/analysis-cache.mjs`。

## 10. 非目标

- 本计划不做永久删除、批量改名、跨文件夹移动或任意路径文件管理。
- 本计划不把 metadata JSON、配置 JSON 暴露为可在网页直接编辑的资产。
- 本计划不把 uploader 自动等同于歌手，也不承诺对缺失 artist 的搜索结果自动正确归因。
- 本计划不把歌词或静态图强制纳入视频/成果的硬完成条件。
- 本计划不重做 CLI 渲染管线、时间线算法或已有的任务执行模型。

## 11. 验收标准

1. 主界面仅在选定文件夹后出现受控 `素材 → 制作 → 成果` 步骤条，且状态完全符合第 6 节。
2. 有既有成片的旧项目无论源素材是否完整都可打开成果；删除最后一个成片后成果立即重新锁定。
3. 成果页为三个局部 Tab；素材页不再对照片做 `slice(0,12)`，可浏览所有图片并在 Lightbox 前后切换。
4. Web 与 CLI 对同一确认后的歌曲字段生成相同 `歌名 - 歌手` 文件 stem；uploader 不被自动写为歌手。
5. 制作页两个开始按钮在桌面同一基线，窄屏无溢出。
6. 素材页不会出现跳回当前素材页的“去补素材”；可执行补救动作的文案明确具体。
7. 第三批上线后，重命名/删除受 token、资产清单、路径/软链、任务运行和冲突规则保护；删除可撤销且不会直接永久删除。
8. 每批通过对应单元/API 测试、前端类型检查/构建与覆盖关键状态的浏览器 smoke test；已存在的无关工具链失败单独报告。

## 12. 风险与待决选择

| 事项 | 风险/取舍 | 待决选择 |
| --- | --- | --- |
| 步骤条严格程度 | 过严会阻碍旧项目回看，过松又退回自由 Tab | 采用本计划的“前进受控、完成可回看、历史成果优先” |
| 无 artist 搜索结果 | 自动猜测容易产生错误文件名 | 下载前强制/显式确认，默认不使用 uploader |
| 大量素材照片 | 一次性渲染/加载会拖慢页面 | 保留缩略图、惰性加载和全量 Lightbox；实现时测真实大文件夹 |
| `.tsuzuri-trash/` | 可恢复但会占项目空间 | 本期不提供自动清理；是否提供“清空垃圾箱”另开确认 |
| 非同 stem 歌词 | 文件操作灵活性与音频事务边界冲突 | 保持唯一 LRC 可用；本批不开放它的独立改名/删除 |
| 文件操作并发 | 任务与改名/删除可能互相破坏 | 服务端任务运行中一律 `409`，不依赖前端禁用 |
