# 胶片模拟

## 目标

给照片加胶片质感，视频和静态图共用同一套效果：

- 小白看描述就能选，熟手看「灵感」行就知道对应哪款胶片或机内风格。
- 用户只做两件事：挑胶片、调强度。
- 整卷统一，个别照片可以单独换。
- 原图永远不改。

## 结构

`film/` 是独立的纯 JS 包，没有依赖。同一份代码跑在 Node（测试、拟合工具）、网页（暗房预览）和 Remotion 无头浏览器（成片）里。以后拆成独立网页或 iOS 版时，直接搬这个包即可。

| 模块 | 职责 |
| --- | --- |
| `src/rolls.mjs` | 16 款胶卷：名称、厂商、灵感来源、描述、场景/气质标签、色彩参数、颗粒/光晕/暗角/闪光参数 |
| `src/color.mjs` | 参数化色彩变换：曝光、色温、反差肩部、分区色相/饱和/明度、分离色调、黑白混合 |
| `src/lut.mjs` | 33³ 三维 LUT 烘焙、三线性采样、`.cube` 读写、base64 编码 |
| `src/develop.mjs` | 冲洗管线：LUT 着色 → 强度混合 → 高光光晕（halation/bloom）→ 暗角 → 闪光 → 颗粒 → 日期戳 |
| `src/grain.mjs` | 确定性颗粒；可整帧烘焙，也可生成叠加贴片 |
| `src/source.mjs` | 读富士 MakerNote 的 FilmMode / 黑白模式，避免重复叠加机内风格 |
| `luts/` | 实测拟合出的 LUT（目前是经典铬） |
| `tools/` | Python 拟合工具（uv 管理，不进运行时） |

处理都在 sRGB 像素上完成，结果完全确定：同一张照片、同一组参数、同一个 seed，像素逐位一致。

## 机内风格识别

富士相机的 JPEG 里记着胶片模拟模式。如果照片已经是经典铬，又选了经典铬，色彩强度降为 0，只加颗粒和光晕。如果照片带着其他机内风格（例如 Velvia），色彩强度乘以 0.6，避免叠得过浓。标准 Provia 视为中性，不做处理。

## 保真度

- **经典铬**是实测拟合，界面标「实测还原」。
  - 数据：用户 X-T1 的 RAF 与其中嵌入的机内 JPEG；解码 284 对，对齐后使用 272 对，其中训练 208 对、留出 64 对。汇总见 [拟合报告](../../film/validation/classic-chrome-summary.json)。
  - 处理：中性解码后对齐，DR200 帧补一档曝光，剔除过曝、边缘和对不齐的像素。
  - 拟合：17³ LUT 正则化最小二乘，以参数化模型为先验，鲁棒重加权。
  - 留出集：每帧有效像素平均 ΔE2000 的中位数 1.81、平均值 2.5；ISO ≤ 800 时平均值 1.84。该指标基于工具的中性解码、色调归一化和对齐流程，不代表任意相机 JPEG 的误差。
  - 留出评估包含离群帧，并另列去离群统计；最终 LUT 拟合排除留出集中识别出的离群帧。按 DR/ISO 分层统计，红、绿、青、品红样本覆盖较少。
- **其余胶卷**是参数化近似，依据公开的胶片特性和机内风格描述调校。由 `test/fingerprint.test.mjs` 约束行为与标签一致：
  - 「黑白」必须无彩。
  - 「浓郁」饱和度必须更高。
  - 「暖调」「清冷」的色偏方向必须正确。

## 存储与解析

- 项目设置：`output/metadata/film.json`
  ```json
  {"version": 1, "roll": "classic-chrome", "strength": 1, "photos": {"a.jpg": {"roll": null, "strength": 1}}}
  ```
  - `roll` 是整卷默认值，`null` 表示原片。
  - `photos` 里是单张覆盖；单张的 `roll: null` 表示这张保留原片。
- 照片重命名在同一项目租约内移动单张覆盖；写入或租约释放失败时回滚照片和设置，检测到后续设置修改时拒绝覆盖。
- CLI：`--film <id|none>` 和 `--film-strength <0-1>` 只替换整卷默认值，单张覆盖依旧生效。
- 渲染前，`applyRenderVariants` 给每张照片写入 `clip.film`：
  ```
  {roll, strength, sourceLook, date, seed}
  ```
  - `sourceLook` 来自 MakerNote。
  - `date` 来自 DateTimeOriginal。
  - `seed` 由照片路径哈希得到。

## 渲染

- 渲染器的 `FilmImg` 在 `delayRender` 内加载原图，按显示尺寸的 1.5 倍缩放后冲洗，产出 blob URL。
- 视频不把颗粒烘进图里，而是每帧换一张预生成的颗粒贴片，以 overlay 方式叠加，颗粒会动。
- 静态图把颗粒直接烘进去。
- 所有出现照片的地方都走 `FilmImg`：日记、胶片条、拍立得墙、开场回顾、静态图。

## 网页暗房

在制作页的「胶片」一栏点「挑胶片」，进入跟随项目白天／黑夜主题的全屏预览。浅色使用白底、暖灰预览区、细分隔线和现有小圆角控件：

- 中间是当前照片的大图预览。
  - 每次打开默认显示同图左右对比，初始左原图、右胶片，中轴固定在 50%。两图使用相同尺寸完整展示构图。
  - 点击中轴中央按钮交换图像和标签，换胶片保留左右顺序。中轴不提供拖动调宽。
  - 图片下方按钮依次以「交换左右」「看完整效果」「开启对比」循环三个查看状态，固定宽度，与「按住看原图」并排。换胶片和照片保留查看模式；选择「原片」时显示完整原图并禁用模式切换。
  - 按住按钮或预览快捷键空格临时看原图，松开后恢复原来的查看模式。中央交换按钮支持 Enter／空格。
  - 开关、交换、对比模式属于当前预览状态，不写入项目设置，也不重新计算胶片效果。
  - `[` `]` 切换照片，底部胶片条标出每张用的胶卷与当前位置计数。点击中间照片保持滚动位置；点击靠近左右边缘的照片时，约 200ms 平滑跟随并露出后续照片。连续点击从当前位置重定向；手动滚轮、触摸或拖动滚动条会立即打断。键盘与减少动态效果采用即时定位。两侧渐隐仅在该方向还有照片时显示。
  - 加载超过 250ms 时，在图片下方预留位置显示灰色状态文字，不覆盖照片、不改变画面尺寸；生成期间保留上一次完成的画面及对应标签，新图和原图都解码完成后一起更新，失败信息立即显示且可重新预览。
  - 页面底色保持不透明，内容进入约 220ms、退出约 160ms；对比与完整效果通过约 170ms 裁切过渡，左右交换及键盘切换即时完成。退出与模式过渡可被新操作打断；减少动态效果时取消位移与展开。
  - 窄屏上下排列预览与胶卷列表；深浅色、减少动态效果和键盘焦点均跟随项目约定。
- 右侧是胶卷列表。
  - 每张卡片都用当前照片实时冲洗出方形预览，右侧名称与完整介绍垂直居中；厂商和灵感来源放在底部通栏，机内风格提示另占通栏。介绍不截断，不因选中展开或改变高度。
  - 按场景或气质标签筛选；`←` `→` 直接换胶卷。
- 顶部切换「整卷 / 仅这张」。
  - 单张设置过的照片可以一键改回跟随整卷。
  - ⌘Z 撤销。
- 每次修改按顺序保存到 `film.json`；完成按钮等待保存结束，失败时保留错误提示并同步已确认状态。同一份设置供视频和静态图共用。
- 暗房与渲染使用同一照片相对路径生成 seed，并读取相同拍摄日期；预览采用缩略图，最终输出采用原图缩放，视频颗粒随帧变化。

## 校验

- `film/`：`node --test`（色彩、LUT、来源识别、确定性、标签行为指纹）
- `cli/`：设置读写、参数解析、clip.film 注入、时间线校验、`/api/film`
- `web/`：整卷/单张解析与撤销的纯函数测试
- `renderer/`：类型检查；本地渲染静态图和视频片段做目检
